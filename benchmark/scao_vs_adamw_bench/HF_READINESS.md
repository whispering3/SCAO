# Hugging Face Readiness Protocol

This protocol produces evidence for an optimizer integration. It is not a
leaderboard and does not permit selecting a best seed or mixing hardware.

## Rules

- Compare AdamW and SCAO with identical model revision, data fingerprints,
  seed, updates, scheduler, batch configuration, LoRA configuration, learning
  rate, and weight decay.
- Report every completed seed. A stopped run is reported as incomplete and is
  excluded from loss averages.
- Compare optimizers only within the same GPU class. H100 measures scaling;
  T4/L4/G4 measure accessibility and compatibility.
- Do not claim an accuracy win from one seed. Use at least two seeds for a
  configuration and report mean plus the individual values.
- Use the supported dense-curvature path for every run. Report whether the
  optional int8 EMA extension was available or the PyTorch fallback was used.

## H100 matrix

Run each command with seeds `42` and `123`. Use a dedicated result directory
per GPU, such as `/content/h100-results`.

| Tier | Model | Optimizers/configurations | Steps | Purpose |
| --- | --- | --- | ---: | --- |
| Small | `Qwen/Qwen2.5-0.5B` | AdamW; SCAO wide 128/20 | 300 | Fast regression and LoRA correctness. |
| Main | `Qwen/Qwen2.5-3B` | AdamW; SCAO full 256/10; SCAO wide 256/10; SCAO wide 128/20; wide 256/40 with int8 and FP32 EMA | 300 | Quality, state, one-sided, and storage-format ablations. |
| Scale | `Qwen/Qwen2.5-7B` | AdamW; SCAO wide 128/20 | 300 | Scaling and HBM behavior. |

Use the same command template, changing only the matrix fields:

```bash
python benchmark/scao_vs_adamw_bench/benchmark_4b.py \
  --optimizer both --model-id Qwen/Qwen2.5-3B --model-revision main \
  --steps 300 --lr 2e-4 --seed 42 \
  --scao-factor-mode wide --scao-max-precond-dim 128 --scao-precond-freq 20 \
  --source-label scao-0.2.4-colab-test-r15.zip \
  --results-dir /content/h100-results
```

For the full versus wide ablation, use `--optimizer scao` with the same seed
and block/frequency, changing only `--scao-factor-mode full` or `wide`. Pair
both with the AdamW JSON generated by the same baseline command.

For the EMA storage ablation, run the same wide 256/40 command once with the
default int8 EMA and once with `--no-scao-use-int8-ema`. This isolates the
memory-format trade-off; it does not replace the AdamW comparison.

## Reviewing evidence

Generate a paired report after copying all JSON records into one directory:

```bash
python scripts/summarize_hf_benchmarks.py /content/h100-results \
  --output /content/h100-results/summary.md
```

The report marks unpaired configurations instead of comparing them. Attach the
JSON records and generated Markdown summary to a draft pull request.
